Check apk-sha256.txt, build-manifest.json and apk-signing-cert-sha256.txt. TEST-ONLY SAFETY BUILD: This beta deliberately packages `android:testOnly="true"` so Android's documented ADB Device Owner escape remains available if its own removal flow breaks. **Do not tap-install this APK**: Android normally rejects test-only packages from a standard installer. Install/update from a trusted computer with USB debugging using `adb install -r -t Brick-V1-1.0.0-beta.3.apk` (choose the correct device using `adb -s <serial>` when more than one is connected). Verify the actual installed package flag and package owner before provisioning. This is a beta-only safety requirement; do not reuse this manifest on the production branch.

EMERGENCY ESCAPE (requires authorised USB debugging/ADB on the exact phone): `adb shell dpm remove-active-admin --user 0 com.brick.safety/.managed.BrickDeviceAdminReceiver`. This is a **last resort** after the normal in-app removal fails; it can release management without reliably reversing all Brick-changed policies, so verify system settings afterward. Confirm with `adb shell dpm list-owners`. Only when no owner/admin remains, uninstall with the Android system UI or `adb uninstall com.brick.safety` (the latter does not itself verify orderly local data purge). Never issue these commands against an unverified phone, never wipe/factory-reset to work around a beta bug.

An already-authorised self-destruct resumes on next app/process start or supported boot broadcast and cannot restart tracking. The in-app remover restores policies, verifies owner/admin release, purges Brick state, and opens Android's uninstall confirmation; Android may still require a tap to finish uninstall. If the handoff was interrupted after purge, reopen Brick to use the recovery uninstall screen. Code/emulator tests do not prove the exact ColorOS behavior without a disposable-device test.

Before installing: record the current installed version/certificate/Device Owner and pairing state. This APK uses the same package and can update an existing compatible signed installation. Do not force a downgrade or silently clear data/uninstall a managed installation. If the installed version is higher than13 or the certificate differs, stop and report it so the build/migration can be corrected. No factory reset is part of this beta handoff.

If ADB is being used, select the intended phone explicitly; never issue management/purge commands against an unverified device. Device Owner provisioning depends on the actual phone/build/setup state. Follow the existing tested provisioning path; do not assume an already-configured phone can always be enrolled without additional steps.
