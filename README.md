# Brick V1 — Phase 1 Child APK

This branch contains only the child-side Android application for Brick V1 Phase 1.

## Phase 1 scope

- minimal child interface;
- high-accuracy fused location foreground service;
- roughly 3-second live updates while the Phase 1 service is active;
- battery and charging telemetry;
- per-device P-256 signing key generated in Android Keystore;
- AES-256-GCM encrypted local journal key generated in Android Keystore;
- durable-before-send packet flow;
- compact 43-byte signed binary location packets;
- sequence numbers and ACK-based cleanup;
- no hard-coded Cloudflare/API credential;
- GitHub Actions APK build and Android lint.

## Child UI

After pairing, the normal app surface stays intentionally minimal: **Safety active**, **I'm Safe**, and **SOS**. The two safety actions are placeholders until Phase 4; they do not falsely claim to send an emergency yet.

## Build

Every push to `phase1-child-apk` runs `.github/workflows/build-apk.yml`. A successful run uploads `brick-child-phase1-debug-apk`, containing an installable debug APK for device testing.

For local builds, open this branch as an Android Studio project using JDK 17.

## Pairing

Phase 1 uses a one-time pairing token generated by the parent Cloudflare dashboard. Enter the Cloudflare Worker HTTPS URL and the pairing token once. The phone creates its own signing key; the private key never leaves Android Keystore.

## Deliberate phase boundaries

Device Owner/self-healing lifecycle work is Phase 2. Activity recognition, speed, GPS quality filtering and fallback positioning are Phase 3. Real SOS/I'm Safe events, history, trips and geofences are Phase 4. Parent UX hardening/map privacy/Device Health are Phase 5. Final reliability/security/privacy qualification is Phase 6.
