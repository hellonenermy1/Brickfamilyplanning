# P8D-088 — capture cancellation and bounded capability lifecycle

Baseline d0429c9ac943fc53b4e60a175410e232976d335f. P2 source orchestration observation supporting existing P8D-002 P1. With readTimeoutMs20, an actual coordinator waiting on a supplied synthetic journal read remains pending after150ms and never reaches release. PHASE8D_CAPTURE_LIFECYCLE_RED.json preserves the observation; an initial fixture missing runtime table exports was corrected before product RED.

Every asynchronous capability now runs through the same bounded path: source pages/DO snapshots, authority checks, journal initial read/publication/readback, retry pause and final full-D1 validation. Per-call budget defaults15s (5–30000ms). Total capture budget defaults240000ms (5–240000ms), measured monotonically. Each call clamps to remaining total time; elapsed checks also refuse a synchronous result that returns after its deadline before the queued timer runs. No archive may report success after a cancellation or elapsed total budget.

A supplied AbortSignal provides cooperative cancellation, including an already-aborted valid capture. Release is independently attempted exactly once with its own per-call budget even if the caller cancels or total capture time is exhausted. A failed, late or stalled release remains CAPTURE_RELEASE_FAILED; source/cancellation/timeout failure otherwise stays redacted CAPTURE_FAILED. Cancellation during release cannot turn into a successful archive. Abort listeners/timers are removed. All configuration/context/key validation must happen before the caller pauses actual writers; invalid configuration is refused without pretending ownership of an unknown source fence.

These are cooperative safeguards, not OS/CPU preemption or guaranteed remote cancellation. A synchronous blocked disk/adapter can delay execution; a real external fence must independently expire and allow urgent safety work to preempt/abort capture. A late encrypted journal write may finish after the coordinator fails. It cannot make that call succeed or authenticate under another context/generation; partial ciphertext is not automatically deleted. Trusted source/authority adapters can lie. This SDK still does not install source writer admission/drain/preemption, an authenticated transport or an independent destination/key.

35 new cases use actual production-schema SQLite and cryptography with supplied authority/DO/journal capabilities. They cover hung journal phases/finalizer/backoff/source/DO, aggregate deadline, cancellation at8 boundaries, pre-abort and release races, late encrypted publication, listener cleanup, private file journal, invalid inputs and synchronous late returns. The existing22 native D1/BLOB cases and actual native41+4/deviceDO source-destruction/restore drill remain separate inherited evidence, not new test counts.

Phase8D NOT PASS; P8D-002 P1 OPEN. The live gate also requires current scoped provider evidence, installed safety-preemptive source fencing/transport, independently controlled private archive/key custody and an isolated cloud recovery/interruption/RTO/RPO/rollback drill. Normal account sign-in alone does not provide these.
