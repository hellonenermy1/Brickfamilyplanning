## Corrected source behavior

Road caches and PMTiles header/directory caches belong to the exact supplied map-object identity. Tile failures, malformed data and expired lookups abandon that generation, discard its road cache and let the next normal request start fresh. An old generation's late failure cannot evict a healthy replacement. At most64 tile entries are retained per map identity, with a3x3 neighboring-tile query. This does not establish total isolate memory across configured map identities or fleet quotas.

Optional route enrichment has a250ms waiting budget. It returns the identical original source2 inertial packet when the map is absent, slow, malformed, incompatible or oversized; it does not fabricate source5, a tighter uncertainty or a snapped coordinate. Healthy maps still attach up to3 plausible corridors without moving the inertial center. Trusted fused/last-known/non-inertial packets do not enter this map path. The existing API routeConstrained=false describes the fallback correctly, and normal signed packets still advance current DO state.

Every compressed range and bounded streamed decoded payload is limited to2MiB; directory and tile gzip decoding use the same bounded reader. Unsupported compression retains the prior fail-open-to-original-packet behavior. Road layers cap4096 features and16384 segments per tile. These refusal envelopes are optional enrichment limits, not a promise to handle arbitrary maps or an overall CPU/RAM benchmark. Timers stop waiting; they cannot preempt synchronous JS, cancel arbitrary bucket effects or prove end-to-end latency. Monotonic elapsed checks prevent publishing a corridor after the enrichment work exceeds its budget.

RemoteMapBucket caches only successfully resolved size/ETag metadata, not a request-owned unfinished promise or rejected promise. This distinction was necessary in actual local workerd tests: an intermediate waiting-budget-only correction did not allow the next request to recover. Failed metadata reads are retried by the next normal request without reopening Brick. HEAD/probe/range transport calls have12s abort signals individually; those transport bounds are separate from the250ms optional location wait, and a custom adapter that ignores cancellation can still finish late. A supplied range ETag that differs from metadata invalidates that metadata and cached ranges; obsolete responses cannot repopulate a replacement generation. An origin without range ETags is not independently version-attested by this check.

There is no new user setting, binding, public route, service, credential, payment/card/R2 dependency or parent-page/APK redesign. R2Bucket is the historical compatibility type; the beta uses the existing no-R2 remote-map adapter. No map installation, live deployment, data deletion or provider request was performed for these fixtures.
