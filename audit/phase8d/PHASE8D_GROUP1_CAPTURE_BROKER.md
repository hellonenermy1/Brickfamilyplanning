# Group1 — staged authenticated capture broker

Group1 NOT READY; Phase8D NOT PASS; P8D-002 P1 OPEN. This is an uninstalled private capability handler/client and native-fixture integration. Production Worker imports, routes, bindings, migrations, controllers, keys and configuration remain unchanged.

## Protocol and permissions

The staged writer wire protocol is now V2. Both message formats and HMAC purpose prefixes changed; V1 requests are rejected before dispatch. No deployed endpoint exists to migrate.

The handler/client use WebCrypto HMAC-SHA-256 with separate request/response purpose prefixes. A request binds POST, the exact configured HTTPS URL, key ID, random request ID, timestamp/window, operation/payload, source SHA, resource-set digest and authority epoch. Responses authenticate HTTP status, that request's ID/digest, the same source/resource/epoch and result/refusal. The client uses edge-compatible manual redirect handling and refuses all3xx responses without following Location; redirect response bodies are cancelled. It also refuses unsigned, modified, cross-request or redirected responses and does no application-level mutation replay. These are staged protocol properties tested below, not an independent security certification.

| Key role | Permitted operations |
| --- | --- |
| capture | Acquire/poll/assert/release capture; bounded page and device-snapshot capabilities |
| runtime-writer | Ordinary/urgent reservation, matching start/cancel and ticket completion |
| external-writer | Target-pinned publication/probe/schema/deployment reservation, matching start/cancel and ticket completion |

Methods and payload keys are closed. There is no network initialize, reset, arbitrary SQL/RPC, restore, credential-export or quarantine-clear operation. External account/database/Worker/host targets must match the trusted catalog. Source/resource/epoch mismatches, cross-role methods and malformed scopes refuse before authority dispatch. The actual current authority epoch is checked around dispatch. Separate key IDs may not reuse key material. Raw32-byte keys are imported as non-extractable CryptoKeys; no production secret is generated or installed.

## Replay, bounds and unknown outcomes

CaptureReplayStore uses actual durable transactions, explicitly initialized from a trusted bootstrap with exact source/resource/epoch. It never initializes from a request. Authenticated nonces are consumed before dispatch, are retained across restart, and cannot be replayed. Uninitialized/corrupt/lost replay state, pin mismatch, clock regression or1024 unexpired nonce capacity refuse. Expired authentication records can be pruned only after their signed window has elapsed; **writer tickets do not expire**. Request windows cap30s with at most5s future clock allowance.

Incoming bodies cap32KiB; replies cap4MiB. Streaming byte limits and complete-call deadlines bound waiting, with best-effort cancellation. HTTPS configuration is required, redirects are refused and messages use no-store. Callback/serialization/transport failures expose generic uncertainty, not source errors/data. Oversized async reply construction initially escaped the local handler catch; awaiting response construction now returns a generic authenticated refusal, with the negative test preserved. Synchronous JS/OS stalls cannot be preempted by these cooperative deadlines, and late remote effects may still complete. A timeout/refusal never proves an operation rolled back or a writer stopped.

The runtime/external controller bridges reserve ownership first, then require a confirmed start acknowledgement before executing work. Only a matching RESERVED writer can be cancelled. A cancellation committed before delayed admission records a permanent role/priority/operation-bound tombstone, so a late admission cannot resurrect it. STARTED or legacy phase-unknown ownership cannot be cancelled; rejected primary/deferred/tool work still retains ownership. Lost start acknowledgements therefore remain unresolved if start committed. Paired start/cancel capabilities are mandatory for V2; legacy controllers remain supported only with legacy receipts. Cancellation failures report uncertainty, never ordinary completion. Tombstones never expire or evict; capacity128 causes permanent capture quarantine and retains unresolved writers. Existing schema/deployment quarantine never resets on cancellation. Native format1 upgrades atomically while preserving all old writers as implicit started; format2 requires its cancellation map and refuses loss/corruption. P8D-093 ownership retention remains in force. The nonce store's bounded capacity is not a production throughput/availability qualification, and an urgent-outage fallback is still required before any activation.
