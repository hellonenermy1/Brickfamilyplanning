# Read-only PITR metadata lifecycle — P8D-090

This correction qualifies the off-platform GET-only metadata checker, not an actual provider account, retention window, active Worker bindings or restore. P8D-002 remains P1 OPEN and Phase8D remains NOT PASS. No cloud request, token creation, new permission, data export, restore, merge, deployment, APK or UI change is part of this work.

## Reproduction

Against source `0dd3e620baa1a1b9277804dda27dc5fd3ca94ff7`, a synthetic supplied body remained pending after the existing 15-second AbortSignal fired. Its transport did not propagate abort to the body. The byte envelope alone could not bound that read, and supplying an abort signal alone does not enforce a deadline on arbitrary supplied capabilities. The actual local CLI also blocked while opening a FIFO plan with no writer; a one-second subprocess guard terminated it. Exact observations are in `PHASE8D_PITR_LIFECYCLE_RED.json`. These are not evidence that the real Cloudflare fetch implementation ignores abort.

## Corrected behavior

- Default per-request budget is 15 seconds, including response headers, all body chunks and parsing. Default total budget is 90 seconds across the existing maximum six GETs. Optional budgets can only reduce these ceilings (minimum 5 milliseconds, safe integers). Monotonic checks reject synchronously late work even if a queued timer has not fired. An optional AbortSignal rejects promptly and prevents subsequent requests.
- Timeout/abort triggers the transport's AbortController and best-effort body cancellation. Each cancellation target is attempted at most once. Cleanup never waits on an arbitrary cancellation hook. A noncooperative late response/read cannot alter the returned receipt or initiate another resource request. Timers/listeners are removed after each call. A reader lock is released when its outstanding read settles; an uncooperative permanently pending reader cannot be forcibly reclaimed.
- The existing 65,536-byte response cap, strict UTF-8/JSON validation, pinned resource names/IDs, GET-only fixed API origin, redirect refusal, dedicated read token and stop-after-first-failure rules remain. Received chunks are copied so a reusable transport buffer cannot rewrite earlier bytes. The validated resource plan is copied/frozen before awaited work so later caller mutation cannot retarget reads.
- Metadata remains sanitized: no token, raw account/resource ID, raw bookmark, provider body or arbitrary exception details enter receipts. `METADATA_TIMEOUT` and `METADATA_CANCELLED` are explicit BLOCKED codes. Earlier completed resource checks remain visible, but any later failure leaves `checksPassed=false`; recovery/window/binding proof flags remain false even on healthy metadata.
- The private plan CLI uses no-follow/nonblocking open, requires a regular private file, reads at most its initial size within the existing 16,384-byte cap, checks EOF and size/mtime/ctime after reading, and decodes strict UTF-8. FIFO/symlink/directory/nonprivate/oversized/changing inputs fail before transport. Local Linux filesystem semantics are tested, not kernel/hardware interruption or ancestor/same-user isolation.

## Verification and limits

`scripts/test-phase8d-pitr-lifecycle.mjs` contains 34 new cases: transport/body/cancel stalls, per-call/aggregate expiry, abort, late transport/read cleanup, synchronous late results, listener cleanup, every historical read position, plan and buffer mutation, redacted refusal, private CLI files/FIFO and injected metadata changes. The inherited eight PITR contract cases remain separate and preserved. Fixtures use synthetic HTTP capabilities and actual local files; no live token or provider request is used. The real hosted audit workflow runs both suites in its existing bounded-capture step.

The correction cannot overcome failed Cloudflare authentication or the historical dedicated-read HTTP401. Google/password sign-in attempts in the exposed browser failed; a user-controlled attempt visibly returned login HTTP403. A fresh login page and further user retry did not establish a usable dashboard session. The browser policy refused settings access, so cookies/data were not cleared and the browser process was not reset. No further login/denied-token retry or broad deployment credential fallback is part of this continuation. These failures do not prove the user's own sessions or provider configuration are absent, or establish their cause.

Operational writer fencing/transport, independent private storage and separate key custody, scheduled protection, actual scoped PITR/configuration and isolated cloud restore/RTO/RPO remain open. Atlas BE-019, deployed release/schema/rollback/capacity and genuine per-ID independent acceptance remain separate unresolved groups. This evidence is partial OPS-002 source-control scope only; no canonical status, owner, criterion or final disposition is changed.
