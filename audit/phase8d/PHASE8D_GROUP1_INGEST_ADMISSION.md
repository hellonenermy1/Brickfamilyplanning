## Four additional routes

`captureUrgentRequestAllowed` now recognizes the exact health, single-location, location-batch and location/live POST routes. It requires an active signed device, bounded body, actual shared schema/packet validation, narrowly fresh evidence and an accepting device rate capability. Source reads and the edge-rate check happen before capture preemption/quarantine; they preserve the original request and do not reserve health counters or append history. False/error/unknown proof remains conservative.

The actual health validator is reused by export; `readVerifiedHealthRequest` factors existing signature/replay-field validation away from the unchanged durable reservation step. Existing local durability evidence validation is reused. Health source-replay state must show a strictly new safe sequence, and malformed/nonfinite/stale/future evidence refuses urgency. Shared signed JSON now requires revoked_at===null rather than a truthy test, so even a non-null zero marker is unauthorized before normal JSON processing. This tightens the existing active-device policy rather than adding a new authentication mode.

Location batches use the same extracted decoder as actual ingestion, preserving the original version/count/length/order/timestamp error behavior. Single uploads retain v1/v2 support; live preview still requires v2. At most20 ordered v2 points and41 bound lookup parameters are inspected. The two-minute admission/fallback freshness policy is narrower than existing ordinary history/replay windows; normal handler windows and physical retry semantics are not changed or claimed qualified.

Durable location eligibility checks real D1 history identities, **not just device_events**. An event marker can precede failed history storage. New or partially stored history therefore remains eligible for urgent retry; a fully stored single/frame does not repeatedly preempt capture. Live preview reads the existing trusted device-object state and uses the same event-time/epoch/sequence ordering as actual latest-state commits. Repeated/older/corrupt/unavailable current state cannot authorize preview urgency. No new DO endpoint or production controller is installed.

## Actual native failures and recovery

The actual composed Worker, signed broker, independent SQLite guard, D1 execution/history and actual device object are exercised. Fresh valid health/single/batch/preview traffic preempts a held capture under healthy admission; forged signatures do not. In broker outage, health reserves its counter only in the real handler. A single-history fault returns no ACK despite an existing event marker; exact retry fills the missing durable row. A20-point batch fault leaves10 history rows and no range ACK; exact retry fills the remaining10 without duplicates.

After a health actor failure, no success ACK is returned and the already consumed replay counter is not erased; the next monotonic heartbeat recovers state. This is the existing counter contract, not guaranteed same-counter replay or physical-outbox recovery. A failed live-preview actor write returns no advancement ACK; the same bytes remain eligible and succeed on retry while state is still older. Restart preserves the latest device preview, health counter, prior SOS/device marker, revocation/device fence and permanent quarantine. Earlier SOS/parent-revocation checks are retained.
