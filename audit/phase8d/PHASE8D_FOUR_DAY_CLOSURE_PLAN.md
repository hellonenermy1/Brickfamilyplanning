The former unconditional Group1-only hold is superseded to this extent by this user-requested replan. Moving on never marks the blocked group closed.
2. Each execution prompt advances the largest practical connected batch through reproduction (when needed), implementation, verification and persistence. Stop for a real dependency/authorization boundary or execution limit, not after one helper or a few tests. Report concrete remaining work and resume exactly there.
3. Do not expand staged signing/monitor/helper abstractions unless a named package cannot meet its existing exit without that change. Preserve useful existing work; stop building adjacent machinery as a substitute for operational proof.
4. Use focused meaningful tests while changing code. Run the complete integration suite at a stable batch boundary and final candidate; repeat only when changes, failures or unresolved concerns invalidate it. Preserve required PR/CI gates.
5. Maintain one current plan and gap register. Update evidence/ledger links in one batch per source milestone rather than repeatedly rewriting large historical documents. No test-count or commit-count progress percentages.
6. Report package state as SOURCE VERIFIED, OPERATIONALLY VERIFIED, ACCEPTED, BLOCKED or NOT YET VERIFIED, with exact evidence. Package totals are a checklist, not an effort-weighted percentage. Keep formal requirement acceptance distinct from implementation.
7. Blockers are raised with the exact missing capability/decision, responsible role, concrete prepared action, impact and next independent work. No token values in chat, broad credential workaround, repeated unchanged denial or silent date extension.
