# Group1 — read-only protected archive health

Group1 NOT READY; Phase8D NOT PASS; P8D-002 P1 OPEN. This is an off-platform read-only primitive and explicit CLI, not an installed backup schedule or monitoring service. No account/provider, source capture, restore, upload, credential creation, cron, Worker/phone/UI change or production bootstrap is performed.

`checkProtectedBackupHealth` takes a trusted health policy, a separately supplied existing backup key and a read capability. The closed policy contains format brick-backup-health-policy-v1; the exact trusted backup context (deployment, sourceSha, backupId, capturedAt, keyId); the encrypted archive's SHA-256 from its trusted publication receipt; and maxAgeMs between one minute and30 days. The policy is not inferred from the untrusted archive and the archive hash is not silently refreshed on each check.

The check reads bounded encrypted bytes, matches the pinned hash, authenticates the existing package and context, then reads again and requires exact encrypted readback. Age comes from authenticated capturedAt against a trusted nonregressing clock, never file modification time. Future capture time, malformed policy/key/context, read/hash/authentication/readback failure or deadline uncertainty cannot become FRESH. There is no automatic mutation retry, new capture, ownership release or quarantine reset.

| Result | Meaning | CLI exit |
| --- | --- | --- |
| FRESH | The exact trusted archive authenticated, matched readback, and its capture age is at most the policy maximum at this check | 0 |
| STALE | Authentication/readback passed, but authenticated capture age exceeds the policy maximum | 2 |
| UNVERIFIED | Input, clock, read, integrity/authentication, readback or timing could not be confirmed | 1 |

The CLI is `node scripts/phase8d-backup-health.mjs ARCHIVE PRIVATE_POLICY_JSON`. Its key is supplied through the existing BRICK_BACKUP_ENCRYPTION_KEY environment contract from the separately controlled operator context; no key is generated or printed. Policy files cap4KiB and archives cap32MiB. The shared reader uses final-component nofollow/nonblocking opens, requires private regular files, enforces complete bounded stable reads and closes descriptors. Existing archive seal/verify behavior reuses the same extracted reader; its I/O-fault regressions remain. Trusted parent paths and same-user process isolation remain operator responsibilities.

Output is redacted metadata only; no device identifiers, location, body, key, file path or provider exception detail. The function temporarily authenticates the payload in memory using the existing package validator. It does not fully validate D1 schema/constraints, restore the backup or prove independent storage/key custody. `restorabilityVerified` is explicitly false even for FRESH. Plaintext string erasure is not claimed. Two successful reads prove the observed check, not future immutability or continuous availability.

Waiting and reads use a cooperative complete-call deadline and best-effort AbortSignal. Node synchronous crypto/OS stalls cannot be preempted; this is not a hard process deadline. No watcher/daemon/cron is installed. Actual scheduled cadence, readback/age/failure alert delivery, interruption/restart monitoring and operational ownership remain unqualified.
